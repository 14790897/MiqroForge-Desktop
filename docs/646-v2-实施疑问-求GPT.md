## Q1：首轮判定后，后续轮次还有没有判定机会？

**现状**：你的评审要求"任何工具执行之前"弹卡（不能出现 search→search→PlanCard）。
**模糊点**：模型首轮只调 1 个工具（如 web_search）→ 首轮判定 0 分不弹 → **第二轮调
write_file 时**怎么办？
- 方案 A：**永不补弹**（首轮即决定）——大任务靠模型主动弹卡（提示词引导）+ harness
  首轮兜底；模型不主动就黑箱执行（小任务可接受，大任务有风险）
- 方案 B：**后续轮次出现写类/危险工具时补弹**——但这就回到"search 成功 search 成功
  PlanCard"的错乱体验
- 方案 C：首轮 1-2 个工具不弹，**但模型第二轮起必须主动弹**（提示词强约束：执行中
  发现任务升级（出现写/上传）必须停下弹卡）——模型主动弹是体验优化，harness 管不了

**我的建议**：A+C 结合——harness 首轮即决（A），提示词要求模型任务升级时主动弹（C，
模型不可靠但这是 9 月可接受范围）。

## Q2：阶段检测（READ→THINK→WRITE +2）的判定边界

**模糊点**：
1. 工具→阶段分类表——web_search/web_fetch/read_file=READ？write_file/create_doc=WRITE？
   exec=THINK 还是独立？upload/send_message=外部（算 WRITE 还是独立）？
2. "跨类型"是**首轮工具集内**同时含 READ+WRITE？还是**跨轮**（第一轮 READ、第二轮
   WRITE）也算？
3. 单写文件（write_file 单独，无 READ）→ 阶段 0 + artifact 2 = 2 不弹 ✓（你的意图？）

**我的建议**：分类表（READ=读类 10+ 工具 / WRITE=写类 / EXTERNAL=上传外发 / EXEC=执行）；
"跨类型"= **首轮工具集**同时含两类以上（READ+WRITE 或 READ+EXTERNAL 等）→ +2；
单写文件不弹（与 Edit 文件自动放行一致）。
