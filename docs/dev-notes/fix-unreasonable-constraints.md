name: fix-unreasonable-constraints
description: 遇到不合理的约束（CI 校验、模板、脚本规则）要主动改掉约束本身并提 PR，而不是改自己的产出迁就
type: feedback
---


遇到不合理的约束——例如 CI 校验脚本要求「代码块必须紧跟标题」这类只能靠迁就才能满足的规则——要**主动修改约束本身**并提 PR，而不是调整自己的产出去绕开；改完要说明修了什么。

**Why:** 2026-09-14 在 PR #1059 上，我先按 pr-template-check 的「代码块紧跟标题」要求改了自己的 PR 描述去迎合脚本，还把这条限制记成了「坑」。用户纠正：「下次记住遇到不合理的地方要主动修改」；我把规则放宽成「节内任意位置有代码块即可」后，用户再次指出「不要求代码块」——说明局部让步不够，要一次想清楚这条规则本身是否该存在（顺带发现该判空逻辑对所有节都失效，一并修掉）。

**How to apply:** 只要 CI / 工具 / 模板规则逼着我扭曲正常做法（描述格式、代码风格、额外步骤），先判断规则本身是否有缺陷、缺陷到什么程度；要改就改到位（小改动单独开 PR），把这当作默认动作，而不是先记一条「坑」去规避，也不要只做让当前这次能通过的最小让步。
