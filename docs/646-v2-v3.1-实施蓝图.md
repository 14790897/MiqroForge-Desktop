## 二、P0 实施蓝图（文件级）

### P0-1：Task / PlanSnapshot / TodoState 数据模型

**新文件** `miqi/runtime/task_objects.py`：
```python
@dataclass
class TodoItem:
    id: str                    # 稳定 ID（如 "research-literature"）
    content: str
    status: str                # pending/in_progress/blocked/completed/cancelled
    kind: str = "plan"         # plan | auxiliary
    blocked_reason: str | None = None  # waiting_user/waiting_permission/...

@dataclass
class TodoState:
    task_id: str
    revision: int = 0
    items: list[TodoItem] = field(default_factory=list)
    # merge 更新（v3.1：plan item 改 content 拒绝）
    def merge(self, patches, *, validate_plan_mutation=True) -> MergeResult

@dataclass
class PlanSnapshot:
    plan_id: str
    goal: str
    steps: list[PlanStep]      # {id, content}——plan-kind Todo 的初始值来源
    plan_version: int = 1
    approved_at: str
    approved_by: str = "user"

@dataclass
class Task:
    task_id: str
    session_key: str
    plan: PlanSnapshot | None
    todo: TodoState
    status: str                # planning/approved/running/completed/cancelled
```

**挂接**：`miqi/runtime/turn_runner.py` 的 turn 创建处——turn 关联 `task`（内存 Task object；
9 月不跨 session 持久化，Task 挂在 session runtime 上）。

**测试**：`tests/runtime/test_task_objects.py`（merge 规则/plan mutation 拒绝/revision 递增）。

### P0-2：Plan confirm → 初始化 Todo

**改动** `miqi/runtime/turn_runner.py`（_harness_plan_confirm 确认分支）：
```python
confirmed → 生成 PlanSnapshot（goal + steps 稳定 ID 化：slugify(步骤内容)）
          → TodoState.initialize(plan.steps)  # 每步 → TodoItem(kind="plan", status="pending")
```
- 稳定 ID 生成：`slugify(content)` + 冲突加后缀（`research-literature`, `research-literature-2`）
- `plan_card_steps` 输出的 `{name, tools}` → 补 `id`（harness 生成——后续模型用 id 更新）

**测试**：确认后 TodoState 初始化（步骤数/kind=plan/status=pending/ID 稳定）。

### P0-3：Timeline 读 TodoState（projection）

**改动** `apps/desktop/.../Timeline.tsx` + `UserInputContext.tsx`：
- Timeline entry 数据源：`{steps: TodoState.items 映射, revision}`（不再 stepStatus 猜）
- 后端在 Todo 变化时发 `todo_state_changed` 事件（payload：taskId + revision + items 摘要）
- 前端 Timeline 按 revision 更新（stale 保护：revision 单调）

**测试**：组件测试（给定 TodoState → Timeline 渲染 pending/in_progress/blocked/completed 各态）。

### P0-4：Tool event fallback（observed_progress）

**改动** `miqi/runtime/turn_runner.py`：
- ToolCallBegin/End 已有 → 维护 `observed_progress`（工具→步骤语义映射，复用 TOOL_DESCRIPTION）
- 没有 Todo 更新时：Timeline 显示 observed（`progress_source="observed"`）
- 模型 todo_write 后：`progress_source="model"`（Todo 为主）

### P0-5：todo_write 工具 + merge

**新文件** `miqi/agent/tools/todo_write.py`：
```python
todo_write(todos: [TodoPatch], merge: bool = True) -> TodoWriteResult
# TodoPatch = {id, status?} | {id, content, kind:"auxiliary", status?}
# 规则（v3.1）：
#  - merge=True（默认）：按 id 合并——只改状态/只加 auxiliary
#  - plan item + content 修改 → 拒绝 PLAN_MUTATION_REQUIRES_RECONFIRMATION
#  - 自动升级 merge（全是指向已有 id 的状态翻转）
#  - revision += 1
#  - 结果回传 summary（见 P0-6）
```
- 注册：`tool_registry_factory.py`
- **is_read_only: true**（permission_engine 6b 分支加 todo_write——Task metadata 变更不审批）
- 提示词注入：复杂任务（3+ 步骤）建议使用（不强制——能力不是门槛）

**测试**：merge 增量/plan mutation 拒绝/自动升级/revision。

### P0-6：summary_for_prompt

**改动** `todo_write.py` 结果：
```json
{"total": 6, "completed": 3, "in_progress": ["生成实验报告"], "pending": 2, "blocked": 0}
```
- 模型读 summary（不塞全列表）
- Prompt 展示："3/6 完成；当前：生成实验报告；待执行 2 项。"

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 模型忘调 todo_write | Tool event fallback（不允许空白）——P0-4 |
| 模型改 plan 步骤 content | merge 闸拒绝 + 提示模型重新 PlanCard——P0-5 |
| Todo 与真实执行不符（模型说谎） | Todo=semantic 定位；ActionGuard 看 ToolResult——v3.1 决策记录 1 |
| Timeline stale（事件乱序） | revision 单调递增保护——P0-3 |
| 实施范围膨胀 | 严格 P0 六步；persistence/priority/跨 session 全部 P1/P2 冻结 |

## 五、P1/P2（冻结清单）

- P2：跨 session / global Todo registry / priority scheduler / todo search / 复杂 reconcile engine
